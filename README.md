# Dashora Organizer

Dashora is a local-first planner for people who want structure without friction.

Think of it as a calm command center for your brain:

- Capture quickly
- Sort visually
- Keep momentum
- Recover safely when life gets chaotic

No account. No cloud lock-in. No backend required.

**Your app data stays local.** Dashora stores your boards, tasks, descriptions,
notes, and sketches in your browser on your device. It does not upload this data
to, or store it on, any server.

**Automatic daily backups are available in the app.** To enable them, open
**Backups**, select a specific folder, and grant the browser **read/write access**
to that folder. Dashora saves its backup copies there; it cannot write folder
backups until you grant access. Daily backup checks run while the app is open.
New backup copies are also generated after an item is **created, updated, or
deleted**. The app keeps the **latest 3 regular backups**, plus **all backups you
explicitly mark as Protected**, which are excluded from automatic cleanup.

Available online at [Dashora](https://dashora.netlify.app/).

## Feature Tour

### Appearance

Open **Settings**, choose **Theme → Light** or **Theme → Dark**, then **Save**.
Dark remains the default. Your choice is saved in this browser, applied before
the page is drawn, and synchronized with other open Dashora tabs.

Light uses the warm background **`#f3f1ed`** consistently across the sidebar,
main pane, and header, with softer card surfaces rather than bright white panels.
Arabic and automatically detected RTL text use **Noto Kufi Arabic** from Google
Fonts, with system fallbacks; Latin UI fonts and rendered monospace code are
preserved. Follow-up inputs and text also detect writing direction automatically.

Both themes cover boards, the dashboard, dialogs, Markdown/RTL editing and
previews, reminders, and native date/time controls. Sketch canvases keep their
original dark background so saved drawing colors remain readable; embedded
images and stored item content are not recolored or modified.

### Notes within an Item

Expand a saved task or reference item and choose **+ Add note** below its
description. Notes have an optional title and their own Plain text/Markdown and
Auto/LTR/RTL controls, using the same formatting, preview, image-paste and undo
support as the description editor. Save the item first when creating a new item.
The note editor is wide on desktop, with a roomy Write/Preview area. Its content
scrolls separately from the header and Save controls, so long previews stay
contained above the footer. It adapts to smaller screens.

With two or more notes, drag a note's grip to place it before or after another
note in the same item. Touch dragging is supported; with the grip focused,
**Alt+Up/Down** also moves the note. The order is saved automatically and used in
copies, share links, full-screen reading and backups. Encrypted reordering asks
for the encryption password, just like editing. Note text stays selectable, and
collapsed notes retain their state when reordered.

Use **Collapse all / Expand all** beside **Notes** to change all notes together,
or click a note heading to collapse or expand it individually;
use its **Edit** or **Delete** button to change just that note. The original
description remains separate and is never automatically split or rewritten.
Notes are distinct from actionable follow-ups.
Click **Description** to collapse the main description without hiding the notes
or other item controls. Items, descriptions and individual notes remember their
open/closed state in this browser across navigation and reloads. New items start
collapsed; new descriptions and notes start expanded. Note states follow their
notes when reordered or deleted, and the full-screen reader shares the same
preferences. Shared readers also remember description/note state per shared
item, with no item text stored in these preferences.

These are browser-local view preferences, separate from exported/backed-up
content; importing or restoring data resets local item view preferences to avoid
applying them to unrelated restored IDs. Collapsing never changes text, note
order, encryption, or backup contents.

Notes are included in search, clipboard copies, share links, full-screen reading,
exports and backups. Encrypted items encrypt their notes together with the rest
of the content; editing or deleting an encrypted note requires the encryption
password. Older items, backups and share links continue to work without notes.
Unprotected notes also follow the Auto-save setting without closing the editor;
protected notes require Save. Unsaved note edits trigger a warning before leaving.

### Follow-ups

from their description and notes:

- Add a follow-up with **Add** or **Enter**.

- Edit with the pencil button or by double-clicking the text. **Enter** saves;

- Follow-up text and completion state are included in exports, backups, shared

Follow-ups do not independently change the parent task's status or count as
tasks in the dashboard.

### Recurring Tasks and Calendar Export

Tasks support a due date/time, colored urgency badges, an optional recurrence
schedule, and an optional recurring reminder time.

| Schedule | When completed tasks reset to To Do |
| -------- | ----------------------------------- |
| Daily | At the next daily reset check |
| Weekly | Mondays |
| Biweekly | The 1st and 15th of each month |
| Monthly | The 1st of each month |
| Specific days | On the selected weekdays |

These are calendar-based reset rules, not a configurable interval measured from
each completion. Checks run when the app starts and periodically while it is
open; they are not a server-side scheduler. Recurring reminder times use the
same schedule.

**Add to Calendar** downloads an `.ics` file for a task with a due date. It contains
the task title and main description, a one-hour event starting at the due time,
and a 15-minute reminder. It does not create live calendar synchronization,
export additional notes, or create a recurring calendar series.

### Editing and Auto-save

The item editor ignores clicks outside its panel. Use **Close** or **Escape**
to exit; unsaved edits trigger a discard confirmation. Successful manual saves
close the editor, while failed saves keep it open with the draft intact.

Enable **Settings → Auto-save items** to save unprotected items and notes after
approximately 1.5 seconds of inactivity without closing the editor. Editing a
note updates only that note, never the main description. Unchanged auto-saves
do not create duplicate backup snapshots.

Protected items and notes require an explicit **Save**; encrypted changes also
require the appropriate password. Save is blocked while an image paste or
another save is still in progress. The app warns before leaving with unsaved
note changes, in-flight saves, or pending backup writes, subject to the browser's
page-exit rules. Do not rely on closing the page to finish saving.

### Share an Item

Use an item's **Share** action, then **Copy link**. The URL contains a snapshot of the
title, main description, ordered notes, writing directions and formats, link,
sketch, task status, due date, recurring schedule/reminder, and follow-ups.
No server-side record or original item ID is needed.
Content is UTF-8 JSON encoded into the URL fragment, so Unicode and Markdown are preserved.
Updating or deleting the original item does not change an existing shared link.

- The complete URL is measured in UTF-8 bytes; URLs **greater than 2,048 bytes** trigger
  an alert that the URL might be too long to work. The full URL remains available to copy.
- Opening a link shows a read-only item without automatically importing it.
- The reader supports description/note collapse and **Collapse all / Expand all**,
  with browser-local preferences separate from the original item's view.
- **Save to board** creates an independent copy in a matching task/reference board.
  Recipients can choose an existing board or create a new one.
- Protected items must be unlocked before sharing. Sharing requires confirmation that
  the URL contains an unprotected copy; passwords and encryption credentials are excluded.
- Anyone with the URL can read the shared content. Shared copies are not password-protected,
  and deleting or relocking the original cannot revoke a link.
- Malformed or unsupported shared links show an error without modifying existing items.
- Sharing works with offline-cached app assets, but recipients still need access to the
  app's address. A localhost or local-file URL is not a publicly hosted app address.
- Shared links are snapshots, not live collaboration, synchronized conversations,
  or invitations to edit the original item.

### Share a Single Note

Use **Share** in a saved note's heading, including in the full-screen reader,
then **Copy link**. This link contains **only that note's title and body**,
preserving Markdown, embedded images, and writing direction. An untitled note
uses the generic title **Shared note**.

The parent item's title, description, other notes, link, sketch, task status,
schedule, follow-ups, IDs, and passwords are not included. Links or images
written inside the selected note remain part of its body.

Recipients see a standalone, read-only reference snapshot and can use
**Save to board** to create an independent reference item, with the note body as
its description. This does not modify or add content to the original item.
The existing URL-length warning and snapshot limitations also apply.

Protected/encrypted items must be unlocked first. Sharing then asks for
confirmation that the selected note will be readable by anyone with the link;
it does not share the password or encrypt the resulting URL.

### Protected Reference Items

- Hide a reference item's title, notes, link, and sketch behind a password prompt
- Use one global password or an item-specific password that overrides it
- Set or change the global password in Settings; new passwords require at least
  eight characters and confirmation
- Passwords are verified with PBKDF2-SHA-256 using random salts and are never stored as plaintext
- Optionally encrypt protected item content with AES-256-GCM
- Encrypted titles, notes, links, and sketches remain ciphertext in IndexedDB, exports, and backups
- Unlock state lasts only for the current page session; reload or use **Lock all** to relock items
- Remembered expansion preferences never bypass the password prompt

Encryption is optional per protected item. Protected items without encryption remain plaintext in IndexedDB, JSON exports, and backup files. Encryption keys are derived for the immediate operation and are never persisted or cached. While an encrypted item is unlocked, its decrypted content necessarily exists transiently in page memory and the rendered interface until the item is locked or the page is reloaded.

Encrypted saves confirm the selected global or existing item password at save time. A new item password entered in the same form is used for that save without asking twice. The password input and derived key are discarded after the operation.

Changing the global password re-encrypts encrypted items that depend on it.
Removing it requires the current password and is blocked while protected items
still depend on it. Item-specific passwords are managed in the item editor.

The encrypted payload covers the title, main description, additional notes
(including their order and formatting settings), link, and sketch. Structural
metadata such as board membership, item ordering, task fields, and the main
description's format/direction remains outside that payload.
There is no password-reset service: a ciphertext backup still needs the correct
password to unlock its content.

### Backup, Restore, and Recovery

- Manual backup anytime
- Automatic backup after item creation, updates, and deletion, as well as note additions, edits, deletions, and reordering, new board/follow-up creation, and daily checks
- Auto-save changes also trigger backups after successful browser storage writes; unchanged auto-saves do not create duplicate snapshots
- Backup writes are queued, with each snapshot captured when requested so later edits do not replace an earlier queued snapshot
- Backup files saved to a user-selected folder
- File names include date/time, reason, and a unique identifier
- Restore or delete backups from the Backup tab
- Protect important backups from auto-pruning
- Protection state stored both in file content and file name
- Retention keeps the latest **3 regular backups**, plus every backup the user explicitly marks **Protected**
- Protected backups do not count toward the three-backup limit and are not automatically pruned

Automatic folder backups require a connected, writable backup folder. A backup
failure does not undo a successful browser save: the app logs the failure and
shows a separate warning. Leaving while a backup write is pending also warns.
Notes, their writing/formatting settings, and their saved order are included;
encrypted content stays encrypted in backup snapshots.

Open **Backups**, select a folder, and grant read/write access to enable folder
backups. Use **Backup now** for an immediate snapshot. The Backups view shows
the reason, date, and item count, and offers Restore, Protect/Unprotect, Delete,
and folder-disconnection controls. Disconnecting leaves existing files on disk.
Protecting a backup only exempts it from automatic pruning; it does not encrypt
the backup file.

Daily checks do not create another daily snapshot if a backup already exists
for that calendar day. They run only while the app is open. Retention applies
across all regular backups, so frequent edits can rotate older files quickly;
protect or copy snapshots you want to keep long-term.

An item-deletion snapshot reflects the data **after** removal. Recovering a
deleted item requires an earlier snapshot; protect important backups before
destructive changes.

Not every interaction creates a dedicated snapshot: quick task-status changes,
whole-board deletions, and follow-up edits/completions/deletions do not each
trigger a new file. Take a manual backup before destructive or bulk changes.

### Import and Export

- **Export** downloads a JSON snapshot of boards, items, main descriptions,
  sketches, follow-ups, and global-password settings.
- Every additional note's title, text, format, direction, and saved sequence is
  included. Encrypted item content remains encrypted in the export.
- **Import** restores that JSON and **replaces all current app data**, rather
  than merging it. The app asks for confirmation and attempts a pre-import backup
  when a usable backup folder is connected.
- Older exports/backups without notes or writing-direction fields remain supported.
  Imported description/note metadata is validated before replacement.
- Import/restore resets local item open/closed preferences so unrelated restored
  item IDs do not inherit an old view.
- Browser-only preferences, such as theme and reminder/auto-save settings, and
  the backup-folder connection are not transferred by the content export.

Export and copy operations are local downloads/clipboard writes; they do not
create a cloud account or synchronize another device. Importing an encrypted
export does not remove its password requirement.

### Offline Use and Installation

- After a successful online load, the service worker caches the app shell and

- Local app assets use network-first updates with a cached fallback; pinned CDN

- Browsers that support PWA installation can install Dashora from their

### Run Locally

The app is static HTML, CSS, and JavaScript: no build step, package installation,
application backend, or account is required. Serve the repository over localhost
rather than opening the HTML directly, so service-worker, WebAssembly, and
secure-context browser features work as intended.

For example, with Git and Python 3 installed, run in PowerShell:

```powershell
git clone https://github.com/mohaidr/focus-board.git
Set-Location focus-board
python -m http.server 8000 --bind 127.0.0.1
```

Open [http://127.0.0.1:8000/](http://127.0.0.1:8000/). Any equivalent static
server can be used instead. For public hosting, serve the repository's static
assets over HTTPS.

The hosted app and a localhost copy have different browser storage. Export/import
is the way to move content between them.

## Data, Privacy, and Storage

### App Data

- Stored as SQLite in browser memory via sql.js
- Persisted to IndexedDB
- Boards, items, notes/order, follow-ups, and password verifiers/salts are saved
  with app data so restored protected items can still be unlocked
- Notes are stored in their saved order inside the item; encrypted notes are
  inside that item's encrypted payload
- Data is scoped to the current browser profile and app origin; there is no
  automatic cross-browser, cross-device, or account-based synchronization

### Browser Preferences

- Theme, auto-save, notifications, auto-delete preferences, selected board, and
  remembered open/closed views are stored locally in the browser
- Shared-reader view preferences use a payload digest rather than storing
  shared titles, descriptions, or URL contents in those preferences
- Theme changes synchronize between tabs; this is not multi-user collaboration
  or general live database synchronization

### Backup Metadata

- The selected backup-folder handle is stored separately in IndexedDB metadata
- The browser can require permission again after reopening or changing settings

### Backup Files

- Backups are JSON files written to your selected folder
- They contain saved content/settings rather than browser-only view preferences
- Files already written to that folder remain independent of browser cache/site
  data cleanup; you may need to reconnect the folder afterward
- If you choose a cloud-synced folder, that provider may sync the backup files
  independently. Dashora itself does not upload them to a server.

### Network and Privacy Boundaries

There is no app backend or automatic content-upload service. Editing, searching,
dashboard calculations, image embedding, and content encryption run locally.
Loading the hosted page, CDN libraries, Google Fonts, or external image URLs
still makes network requests to their respective providers.

A share link contains a readable copy of the selected item, even if the original
was encrypted. Treat it as sensitive data and share it deliberately. Password
protection without encryption only hides content in the interface.

## Browser Support and Limitations

- Use a modern browser with IndexedDB, WebAssembly, and Web Crypto support.
  HTTPS or localhost is recommended for the full feature set.
- Folder backups use the File System Access API and directory-picker support,
  commonly available in Chromium-based browsers such as Edge and Chrome.
  In browsers without it, use JSON export/import for manual recovery copies.
- Notification, vibration, clipboard, pen-pressure, and install options vary by
  browser/device and permissions. Audio is subject to autoplay restrictions.
- Background or fully closed apps do not provide reliable scheduled reminders.
- Browser quotas, private-browsing rules, storage eviction, or clearing site
  data can affect persistence. Keep external backups of anything important.
- Large embedded images/sketches increase database, export, backup, and share-link
  size. Shared URLs are not a replacement for a file-transfer service.
- The app has no backend-driven collaboration, live comments, cloud sync,
  password recovery, or calendar synchronization. Additional notes are local
  content blocks, not a chat thread.
